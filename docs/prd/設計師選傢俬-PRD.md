# 設計師選傢俬 — 功能實現需求規格（PRD）

最後更新：2026-10-17

> **範圍**：只涵蓋設計師面向的產品瀏覽、搜尋、模型與權限。對應母文件《FDS-2.0-需求規格》的 **R3（搜尋優化）**、**R6.1（設計師工具）**、以及 **R6.2 中與設計師相關的部分**，並對應新版 Sitemap 主區塊「**設計師選傢俬**」6 個子頁面。
> **母文件**：`docs/prd/FDS-2.0-需求規格.md`

## 1. 目標與使用者

### 1.1 Personas

| 角色 | `UserRole` | 主要需求 |
|---|---|---|
| 設計師 | `designer` | 快速找到特定產品（墨綠色梳化、橙色 1.5 米梳化、特定尺寸辦公台）、取得規格／價錢／圖片／PDF、拉出 SU／3D 模型畫圖 |
| 項目經理 | `pm` | 找產品做方案與快速報價 |
| 其他同事 | `uploader` / staff | 搜尋並產生內部訂單給傢俬組 |
| 客戶 | `client` | 只限客戶專區（本文件不含） |

### 1.2 核心目標

1. **搜得準**：以顏色、材質、尺寸、類型、現貨／訂製精準篩選。
2. **睇得全**：A 類（公開）與 B 類（內部 3,000–4,000 款）產品對設計師一併開放。
3. **拎得快**：直接看到對應 PDF 頁面與圖片，以及 SU／3D 模型連結。
4. **落得到單**：設計師可直接選產品產生「內部訂單」給傢俬組（不暴露成本價）。

### 1.3 現況事實（程式現狀，作為 Gap 依據）

- 「設計師選傢俬」6 個子頁面**全部是 placeholder**（`PlannedPage`），未實作（`navConfig.ts:37-49`，無對應 `MOVED_PAGES`）。
- 真實搜尋引擎 `src/lib/productCatalogQuery.ts` 只支援：來源（A／B）、關鍵字、廠家、level1／level2、現貨。**缺顏色／材質／尺寸篩選**。
- 較完整的篩選器只存在於客戶端 `CustomerProductSearchView.tsx`（材質、價格、尺寸範圍）與一個未被路由的 mock `ProductSearchView.tsx`（顏色、現貨、A/B/C）——可直接重用邏輯。
- **SU 模型、3D 模型、產品目錄 PDF 在資料庫與程式中完全不存在**（無表、無欄位、無 Storage）。
- A／B 類**不是欄位**，而是以資料來源區分（`shopify`＝A、`system`＝B）。
- **無「內部訂單」概念**；成本價 `cost_price` 目前直接傳給呼叫方，**無角色遮罩**。
- 角色有 `admin/uploader/pm/designer/client`，但菜單只有 admin／非 admin 兩層，**無設計師專屬可見性**。

## 3. 功能需求

優先級：**P0**＝本期必做；**P1**＝次期；**P2**＝後續。

### D-1 產品類型（搜尋主入口）— P0

設計師進入後的主要工作畫面：上方篩選列 ＋ 產品卡片／列表。

#### D-1.1 篩選條件
- **產品類型**：level1／level2 分類（沿用 `product_category`）。
- **顏色（多選）**：可同時選多個顏色（例：墨綠 ＋ 橙色）。
- **材質**：木皮面、布料等（取材質 tag，沿用 `CustomerProductSearchView` 的 `MATERIAL_TAG_RULES` 規則）。
- **尺寸**：長／闊／高範圍（沿用 `dimension_l_mm / w_mm / h_mm`）。
- **現貨／訂製**：沿用 `in_stock` ＋ `customize`。
- **快速篩選**：常用家私（D-3）、最新產品（D-4）。
- **廠家**：沿用 `factories_display_name` 下拉。
- **產品來源**：A 類（shopify 上架）／B 類（系統產品目錄）／全部。
- **驗收**：上述條件可疊加；結果即時更新；篩選狀態可一鍵清除。

#### D-1.2 搜尋
- 關鍵字同時比對 **title／型號（`model`）／SKU**。
- 支援顏色、材質等自由文字模糊比對（延用現有 `matchesSearch` 邏輯並擴充欄位）。
- **驗收**：輸入「梳化 墨綠」可命中顏色＝墨綠的梳化；輸入型號可精準命中。

#### D-1.3 排序與分頁
- 排序：相關度、最新、價錢（低→高／高→低）、尺寸。
- 分頁沿用 `productCatalogQuery` 的 `page/page_size`。

#### D-1.4 優先顯示廠家現有款
- 排序／標記上，**優先顯示廠家現有款**，將「需訂製／可能不存在」的款式降後或標示。
- 依據 `in_stock`／`customize` 判斷。
- **驗收**：預設排序下，現貨／廠家現有款排在訂製品之前。

#### D-1.5 產品卡片內容
每張卡片顯示：相片、名稱、**尺寸 L×W×H**、材質、顏色、**中間價**（見 D-8.3）、交期、所屬廠家、對應 **PDF 頁連結**（D-2）、**SU／3D 圖示**（D-5／D-6，有才顯示）。
- **不可顯示成本價**（見 D-8.3）。

---

### D-2 產品PDF（目錄與 AI 分頁）— P0

#### D-2.1 PDF 持久化與關聯
- 現況：AI 匯入只抽產品圖，**PDF 本身不保存**。
- 需求：保存廠家目錄 PDF，並與**廠家**及**產品**建立關聯。
- 新增資料（見第 4 節）：`factory_catalogs`、`factory_catalog_segments`；產品可回指目錄頁。

#### D-2.2 AI 自動切割分頁／分區
- 上載 PDF Catalog 時，AI 自動辨識分段（例：第 1–17 頁辦公台、第 18–28 頁老板台、會議椅…），並產生**頁面→分類**對照。
- 沿用現有 `AIProcessorView` ＋ edge function `supabase-functions-gemini-pdf-catalog`（現為單頁切圖），新增「分段／分類」輸出。
- **驗收**：上載一份目錄後，系統自動列出分段（起始頁、結束頁、分類名），可人手修正。

#### D-2.3 設計師查看 PDF 頁面與圖片
- 搜尋結果可直接看到**對應 PDF 頁面及已切出的產品圖片**，無需等待完整報價單分析。
- **驗收**：由產品卡片可開啟其來源 PDF 頁；PDF 檢視器支援翻頁。

#### D-2.4 頁面名稱調整
- 區分「**報價 PDF**」與「**產品目錄 PDF**」（目前兩者都指向同一 `ai-processor`）。
- 驗收：上載入口與清單標題明確區分兩種類型。

#### D-2.5 設計師上載目錄（待審，不直接入庫）
- 入口在設計師選傢俬（產品類型 `FurnitureSearchView` 與產品 PDF）。設計師選擇或輸入廠家，上載產品目錄 PDF。
- 解析沿用廠家上載精靈（`AIProcessorView` 的 `gemini-pdf-catalog`）與逐件現有分類歸類。對不上現有 `product_category` 的名稱留空，不可自創分類。
- 結果寫入待審批次，記錄上載人、廠家、原始 PDF、時間。**未通過不得出現在產品庫。**
- 管理員在「設計師目錄審核」修改欄位與分類，可逐件或批量通過／拒絕。通過後入庫；拒絕保留原因。
- 設計師可查看自己上載的狀態與拒絕原因。RLS：只能讀自己的批次；通過／拒絕只限 `admin` 的 RPC。
- **驗收**：設計師上載後，產品搜索找不到這些產品；管理員通過後才出現；拒絕原因設計師看得到。

### D-3 常用傢俬（愛心收藏）— P1

- 設計師可對產品**加入／取消愛心**，收藏為個人清單（per-user）。
- 「常用傢俬」頁與 D-1 快速篩選共用同一資料。
- **驗收**：加入愛心後即時出現在「常用傢俬」；不同使用者清單互不影響；可由清單直接選產品下單（D-8.4）。
- 資料：`designer_favorites (user_id, product_id, created_at)`。

---

### D-4 最新產品 — P1

- 以 `created_date` 排序展示最新上架產品。
- 可標示「新產品」徽章與可選的即時通知。
- **驗收**：新產品自動出現在列表頂部；可設定只看最近 N 天。

---

### D-5 SU模型 — P1

- 產品可綁定 **SU 模型檔案／連結**。設計師使用的檔案格式是 **SKP**。
- AI 生成的 SU 模型與上載模型同一格式：參數化幾何引擎算組件，SketchUp 官方 C SDK 在 Windows SKP Worker 寫成 SKP，不用 OpenSKP。GLB 只供 3D 預覽（D-6）。
- 設計師可在產品頁檢視／下載／複製模型連結。
- **愛心小工具（D-7）**：選中產品後經 API 拉出模型供畫圖使用。
- **驗收**：有模型的產品在列表顯示 SU 圖示；點擊可取得模型。
- 資料：`product_models (product_id, type='su', url, format, thumbnail)`。

---

### D-6 3D模型 — P1

- 同 D-5，綁定 **3D 模型**（glb／gltf 等）。
- 設計師可在產品頁預覽／下載。
- 資料：`product_models (… type='3d' …)`。

---

### D-7 愛心小工具（設計師工具）— P1

- 一個浮動／嵌入式工具：顯示目前選中產品的 **SU／3D 模型連結**。
- 選中產品後透過 **API 拉出模型**，供設計師畫圖。
- **驗收**：在 D-1 選中產品後，小工具即顯示可拉取的模型並提供複製／下載。

---

### D-8 全公司開放與權限 — P0（開放）／P1（內部訂單）

#### D-8.1 角色基礎可見性
- 讓 `designer / pm / uploader` 等非管理員角色可見「設計師選傢俬」全部功能。
- 目前只有 admin／非 admin 兩層；需擴充為角色層級（見第 5 節權限矩陣）。
- **驗收**：設計師登入後可見 6 個子頁並可操作；客戶角色不可見。

#### D-8.2 A／B 類產品開放
- A 類（公開）與 B 類（內部）產品對設計師一併可搜尋。
- 建議新增明確欄位 `product_class`（'A'|'B'）或可見性欄位，取代目前「靠資料來源推斷」的隱性做法。
- **驗收**：設計師在同一搜尋頁可切換或一併看到 A／B 類產品。

#### D-8.3 成本價遮罩與中間價
- **成本價 `cost_price` 不顯示給設計師／PM**。
- 改以「**中間價**」顯示——**賣價 × 0.8**（已決議，見第 7 節）。
- 實作要點：查詢層（`productCatalogQuery`）與回傳物件（`ProductSelectorModal.onSelect`）都要依角色遮蔽 `costPrice`；前端 mock 權限旗標 `'查看成本'`（`constants/analytics-mock.ts`）可作為角色判斷參考。
- **驗收**：以 designer 角色查詢，回傳不含成本價；畫面顯示中間價；admin／傢俬組可見成本。

#### D-8.4 內部訂單
- 設計師／同事可直接在系統選產品並產生**「內部訂單」**給傢俬組。
- 現況：系統**完全無此概念**（無表、無元件）。
- 需求：內建內部訂單建立、明細（產品、數量、分區可選）、狀態流（提交→傢俬組處理）。
- **驗收**：設計師把產品加入內部訂單並提交；傢俬組可收到並檢視。
- 資料：`internal_orders`、`internal_order_items`。

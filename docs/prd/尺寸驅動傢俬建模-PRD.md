# FDS 尺寸驅動傢俬建模 PRD

版本：1.0（需求草案）  
日期：2026-10-28  
狀態：待產品審閱；本文件不代表功能已實作或部署。

## 1. 產品決策與背景

停止使用 Tripo，將建模主流程改為「既有模型優先 → 原始資料讀取 → 結構與尺寸確認 → 確定性幾何建模 → 驗收 → 模型庫」。

目前的問題是生成結果不能穩定還原產品。圖片未提供的尺寸與背面結構可能被推測；中間生成的三視圖可能引入偏差；可開啟的模型檔不代表外形、尺寸或零件正確。

AI 的職責是協助整理證據、辨識零件及提出建議。已確認的尺寸與幾何規則控制模型，使用者能追溯每個關鍵尺寸、修改零件、檢查結果。

## 2. 目標與非目標

### 目標

- 先找可沿用的原廠、上傳或歷史模型，減少重複建模。
- 讓已知、推測、缺失與有衝突的資料清楚分開，避免 AI 推測被當作量測事實。
- 修改尺寸或結構時，可以重建預覽而不必再次呼叫 AI。
- 保留零件名稱、層級、尺寸與版本，支援可編輯 SKP 交付。
- 以可重現的驗收案例衡量準確度，不以生成成功率代替品質。

### 非目標

- 不承諾任意單張照片能精準還原實物或隱藏結構。
- 首期不承諾自動生成生產圖、榫接、五金加工資料或製造級公差。
- 不把全模型縮放當作板厚、腳距、曲面等局部幾何修正。
- 不引入另一個黑箱圖片轉 3D 服務替代 Tripo。
- 不因產品屬於沙發、辦公椅或曲面傢俬而一律禁止；按資料完整度及幾何能力逐件判斷。

## 3. 使用者與核心情境

| 使用者 | 情境 | 預期成果 |
|---|---|---|
| 設計師 | 將產品放入空間方案 | 尺寸可信、外觀經核對的模型 |
| 產品資料維護者 | 補齊圖片、尺寸與原廠模型 | 可追溯、可重用的產品模型資料 |
| 建模人員 | 修正 AI 辨識或處理特殊造型 | 可編輯零件、明確缺項與版本差異 |
| 驗收人員 | 判斷模型是否可以交付 | 原始依據、檢查結果與驗收紀錄 |

典型案例：產品資料提供桌寬 1,400、深 700、高 750 mm，圖紙提供桌板厚 25 mm，照片可確認四腳，但沒有腳距。系統顯示腳距缺失，不默認為已量測。使用者補資料或接受估算後可生成草稿；未解決的關鍵估算不能通過正式驗收。

## 4. 現況盤點與沿用原則

以下為 2026-10-28 本機程式與文件盤點，不代表線上版本或實機驗收狀態。

| 能力 | 已見實作 | 本次方向 |
|---|---|---|
| 產品模型庫 | `src/lib/productModels.ts`；模型列表、登記、下載、SKP 任務與預覽 RPC | 沿用模型關聯、權限與私有檔案流程 |
| 參數幾何 | `src/lib/furnitureParametric.ts`；固定類型及自訂零件、輪廓／路徑相關能力 | 擴充參數約束與編輯能力，不另建一套幾何引擎 |
| 結構檢查 | `src/lib/furnitureStructure.ts`；零件數、接合、對稱、總尺寸等 | 區分硬性錯誤與待確認資訊，補充來源及驗收 |
| AI 讀圖 | `supabase/functions/generate-furniture-model/index.ts`；分類與零件辨識 | 擴充證據、缺項及衝突輸出 |

## 5. 使用流程

1. 選定產品與變體，查詢使用者有權存取的既有模型。
2. 有模型時提供預覽、版本資訊、核對及沿用；沿用不呼叫 AI、不建立生成任務。
3. 沒有合適模型時，整理產品照片、原廠尺寸圖、產品尺寸及文字說明。
4. 確認目標是單件產品或明確指定的整組；多張視角圖不可當作多件產品。
5. AI 提出零件、尺寸、接合關係及待確認問題。
6. 使用者確認資料，修正尺寸或結構，選擇補資料或接受估算草稿。
7. 程式建立幾何並執行檢查；預覽可選取零件、修改參數及重建。
8. 比對原圖與模型，完成品質驗收；需要 SKP 時另執行輸出及格式驗證。
9. 儲存版本、來源、驗收結果及模型檔，供後續沿用。

## 6. 功能需求

### FR-01 停用 Tripo

- 移除新生成入口，後端同時拒絕新的 Tripo 提交，包括舊前端及直接 RPC 呼叫。
- 停止尚未向供應商提交的排隊任務，記錄停用原因，不自動轉往其他服務。
- 已取得供應商 task ID 的任務可完成既有狀態查詢及下載；不得重新提交或增加新生成費用。
- 提交結果不明的任務標記待處理，不自動重試。
- 保留已生成模型、點數紀錄、失敗紀錄與原有下載權限，不刪除歷史資料。
- 清理未完成任務後才移除供應商憑證與剩餘整合；不得影響同一 Worker 的 PDF 或其他任務。

### FR-02 既有模型優先

- 依產品、變體及現有關聯查詢上傳與歷史模型，不用最近少量紀錄判定「沒有模型」。
- 顯示格式、來源、版本、尺寸、預覽狀態與驗收狀態；缺資料明確顯示未知。
- 不同尺寸或結構變體不得自動視為同款可沿用。
- 沿用保留來源關聯；修改建立新版本，不覆蓋原始模型。
- 上傳模型可直接使用既有預覽／下載流程，不要求虛造參數 JSON。

### FR-03 原始資料與尺寸證據

- 優先沿用產品圖片、附件及尺寸欄位，允許補充圖片與尺寸圖。
- 每個來源保留檔案引用、頁碼或圖片位置（適用時）、產品變體及版本。
- 每個尺寸記錄：數值、原始單位、標準化 mm、來源、讀取方式、確認者及確認時間。
- 資料狀態至少包含已確認、待確認、估算、缺失、有衝突。AI 自報信心不能等同已確認。
- AI 讀到圖紙標註仍需保留原文與位置，供使用者核對；AI 生成三視圖不得成為量測證據。
- 多來源尺寸衝突時並列候選，由使用者選定採用值並記錄理由，不靜默取平均。
- 整組與單件尺寸必須分開；不能直接將整組尺寸套在單件模型。

### FR-04 結構與尺寸確認

- 同屏查看原始資料、零件清單、尺寸表及 3D 預覽；點選零件可高亮對應模型。
- 零件具有穩定 ID、名稱、用途、數量、形狀、位置、方向、尺寸及接合關係。
- 可以新增、刪除、複製零件及修正接合；刪除被引用零件前顯示受影響關係。
- 關鍵尺寸由模型結構決定，例如總尺寸、板厚、腳距、座高、層板位置，不能只要求長寬高。
- 缺少建立幾何所必需的值時，必須補值或明確接受估算，否則只能保存待補資料草稿。
- 接受估算不會把來源改成已量測。仍可生成帶有「估算草稿」標記的預覽。
- AI 重辨識提出新建議，不覆蓋人工確認值；使用者逐項採用或拒絕差異。

### FR-05 確定性建模與局部修改

- 沿用現有自訂零件與幾何能力；固定模板只有在符合已確認結構時才可作為捷徑。
- 以尺寸及約束建立零件，例如桌板置頂、腳頂接桌板底部、左右腳對稱；不可單靠全體頂點等比例縮放。
- 修改桌寬時，按約束調整桌板及腳位置，已鎖定板厚、腳徑不得連帶變形。
- 約束矛盾時指出相衝突的數值與關係，保留最後有效預覽，不自行改寫已確認值。
- 相同輸入、參數及引擎版本應得到相同幾何；純參數重建不呼叫 AI。
- 無法表達的曲面或結構顯示具體缺口，提供補輪廓、沿用零件或人工修模路徑，不靜默換成近似模板。
- 草稿可保存不確定資訊；無效幾何、非有限值、零或負尺寸等硬性錯誤不得輸出為可用模型。

### FR-06 預覽、品質與驗收

- 提供旋轉、縮放、平移、重設，以及正面、側面、頂面和透視視角。
- 顯示尺寸與零件清單，可與原始照片／圖紙並排比較；有校準資料時才提供對齊比較，不把透視照片直接當作正投影量測圖。
- 檢查零件數、總尺寸、接合、預期對稱、懸空及幾何有效性；特殊懸掛或非對稱結構以確認的結構定義為準，不能套用一律落地或對稱的規則。
- 區分程式檢查與人工外觀驗收。程式通過不能自動證明模型與實物一致。
- 正式驗收需全部關鍵尺寸有依據、無未解決的關鍵衝突、檢查通過、指定人員完成外形核對。
- 任何結構或尺寸修改均產生新版本並重新驗收，不能沿用舊版通過狀態。

### FR-07 儲存與輸出

- GLB 用於系統預覽；SKP 用於可編輯交付。沿用既有格式及模型資產契約。
- 儲存原始資料引用、確認參數、零件、約束、引擎版本、檔案 hash 及驗收紀錄。
- 同一版本的預覽及 SKP 必須來自同一份已確認幾何。
- SKP 保留可辨識零件名稱與可編輯群組／元件，不接受只有整件不可分辨網格的輸出作為零件可編輯驗收。
- Worker 不可用或輸出失敗時保留參數與可用預覽，顯示原因及重試方式，不標記 SKP 已完成。
- 格式驗收需在真實 SketchUp 開啟、量測、修改零件、儲存及重開；副檔名正確或檔案可解析不足以通過。

## 7. 狀態與版本規則

以下為產品語義，實作優先映射到現有欄位及任務狀態，不要求直接新增同名 enum。

| 維度 | 狀態 |
|---|---|
| 建模資料 | 待補資料、待確認、可建模 |
| 模型品質 | 估算草稿、待驗收、已驗收、驗收不通過 |
| 產物 | 未生成、生成中、預覽可用、輸出失敗、指定格式可用 |

「預覽可用」「SKP 可用」「已驗收」互相獨立。歷史模型若沒有驗收證據，顯示未驗收，不回填為已驗收。已驗收也不代表可直接用於生產。

耗時任務綁定模型版本及參數 hash。使用者切換產品或修改版本後，舊任務只能回寫原版本，不覆蓋目前畫面或新版本。相同版本重試沿用可用產物，避免重複生成。

## 8. 權限、相容與介面約束

- 沿用既有使用者角色、模型存取 RPC、RLS 及私有 `product-models` bucket。
- 編輯及驗收操作由既有角色權限映射；開發前列出實際授權矩陣，未授權者不能透過 API 繞過 UI。
- 衍生預覽、來源圖片及原檔使用一致的授權邊界；簽名網址到期可重新授權取得，不公開資產。
- 舊模型可讀取、下載、預覽；缺少新 metadata 時顯示未知，不破壞舊契約。
- UI 使用 `src/components/ui` 共用元件：`Modal`、`Select`、`Switch`、`Checkbox`，確認操作使用共用 `confirm()`。
- 修改 Edge Function 前確認前端實際呼叫的 slug；部署至該 slug，部署後讀回來源驗證。

## 9. 驗收案例與品質基準

首期建立至少 6 件固定產品樣本，包含規則桌、櫃、斜腳椅、彎曲框架、軟包或曲面產品，以及僅有照片且資料不足的案例。每件保留來源、預期零件、關鍵尺寸及可支援範圍；複雜案例可以正確轉人工處理為預期結果，不能偽稱自動還原成功。

| 編號 | 驗收情境 | 通過條件 |
|---|---|---|
| AC-01 | 存在可沿用模型 | 可選定版本；沒有新增 AI 呼叫或生成任務 |
| AC-02 | 停用 Tripo | 新舊前端及直接後端提交均不能建立新供應商任務；歷史模型可用 |
| AC-03 | 缺少腳距 | 顯示缺項；接受估算只能生成草稿，不能成為已驗收 |
| AC-04 | 圖紙與產品尺寸衝突 | 保留兩個來源，要求選定採用值及理由 |
| AC-05 | 修改桌寬 | 桌寬及受約束位置改變；鎖定板厚與腳徑不變；不呼叫 AI |
| AC-06 | AI 重新辨識 | 已確認值保留，差異逐項可採用 |
| AC-07 | 零件斷開或約束矛盾 | 顯示具體零件與原因，阻止正式驗收 |
| AC-08 | 多視角／多人桌照片 | 視角不變成多件；單件／整組依明確選擇及相應尺寸處理 |
| AC-09 | 超出幾何能力 | 說明缺口並提供人工或既有模型路徑，不靜默套模板 |
| AC-10 | SKP 往返 | 在指定 SketchUp 版本開啟、修改零件、儲存重開後尺寸及層級正確 |
| AC-11 | 版本競態／Worker 失敗 | 舊任務不覆蓋新版本；失敗保留確認資料及有效預覽 |
| AC-12 | 越權與歷史模型 | 越權讀寫遭拒；缺新欄位的歷史模型仍可正常使用 |

尺寸驗收分兩層：

- 幾何對確認參數：首期以每個關鍵尺寸絕對誤差 ≤ 1 mm 作為數位建模及匯出目標；這是產品驗收目標，不是現有能力承諾。若既有檢查容許範圍較寬，需調整或明確記錄差異。
- 模型對實物：必須有原廠圖紙或量測值及其精度；照片估算不得宣稱達到 1 mm，也不以此承諾製造精度。

外觀由指定人員逐件核對輪廓、零件數量、開孔及支撐形式，記錄通過或具體差異。首期不設定缺乏依據的「AI 相似度 95%」指標。

## 10. 分期交付

### 階段一：停止新 Tripo 生成與契約盤點

交付入口及後端停用、歷史任務處理、PMS／FDS 能力對照、資料模型差異清單、固定驗收樣本。完成條件為沒有新 Tripo 提交，既有模型與其他任務不受影響。

### 階段二：可控建模閉環

交付來源與尺寸確認、零件編輯、約束重建、草稿／驗收狀態、既有模型沿用及版本管理。先以現有引擎可表達的真實產品跑通流程；其他產品保留補資料及人工處理入口。

### 階段三：SKP 交付驗證與複雜造型擴充

沿用現有 Worker 完成同版本幾何輸出、命名元件及 SketchUp 往返驗收。依樣本中的實際缺口擴充輪廓／路徑／曲面能力；不將既有 Worker 誤列為全新建置，也不以安裝成功代替模型驗收。

每階段先在測試環境完成回歸與實際操作，再依專案既有發布流程上線。資料遷移採相容擴充；回滾可關閉新建模流程，但不得重新開啟 Tripo 付費生成。

## 11. 指標、風險與實作前確認

追蹤既有模型沿用率、首次驗收通過率、每件人工修正時間、缺資料中止率、SKP 往返通過率，以及每個已驗收版本的 AI 呼叫次數。試點先建立基線，除上述明確驗收條件外，不預先捏造效能或品質提升百分比。

主要風險為來源資料不足、錯誤 OCR、過度約束、現有幾何能力與需求不一致，以及 SKP 寫出後的元件或單位差異。分別透過來源核對、衝突提示、約束診斷、逐件能力判斷及實機往返測試處理。

實作前需補齊：

1. PMS 線上可重用的產品、尺寸、附件及模型契約清單。
2. 既有 FDS 儲存及 RPC 對來源、約束、驗收 metadata 的容納方式與必要擴充。
3. 實際編輯／驗收角色授權矩陣。
4. 六件試點產品的原始資料、關鍵尺寸與驗收人員。
5. 支援的 SketchUp 版本、Worker 依賴及實機驗證環境。

以上是開發前需要完成的查核工作，不影響本 PRD 已確定的「停用 Tripo、既有模型優先、尺寸與零件可追溯可修改」方向。

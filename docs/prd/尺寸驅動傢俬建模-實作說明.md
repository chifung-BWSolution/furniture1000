# 尺寸驅動傢俬建模：實作說明

對應 `尺寸驅動傢俬建模-PRD.md`。這份只記實際落地的契約與未完成項，需求本身以 PRD 為準。

## PMS／FDS 能力對照（2026-10-28 查 PMS 正式庫 `kqwktnplkqucsbasyfjl`）

PMS `public` schema 沒有產品尺寸、3D 模型、模型版本或驗收資料：名字含 width／depth／height／size 的欄位只有
`bwa_*`／`bwf_*` 專案及提案的場地面積（`size`、`actual_size`、`height_to_*`）和附件的 `file_size_bytes`；
`bwf_products` 沒有尺寸欄位。所以這次只擴充 FDS 自己的 `furniture_models`，不碰 PMS 契約，也不從 PMS 讀尺寸。

## 資料對應

| PRD 概念 | 存放位置 |
|---|---|
| 模型版本 | `furniture_models` 一列＝一個版本；`parent_id`＝修改自哪個版本 |
| 參數幾何 | `furniture_models.parametric`（`ParametricModel`，含 `custom_parts`、`structure_parts`、`engine_version`） |
| 尺寸證據 | `parametric.evidence`（`ModelEvidence`：每個尺寸的候選來源、原文、圖號、狀態、採用值、理由、確認人） |
| 品質狀態 | `furniture_models.quality_status`：`unreviewed`（舊版本，沒有證據）／`draft`（估算或有阻擋項）／`pending_review`／`accepted`／`rejected`，由伺服器按證據推算，前端不能直接設 |
| 同一幾何去重 | `params_hash`＝`sha256(parametric::text)`；同產品同參數沿用舊版本及其檔案 |
| 驗收紀錄 | `review`（決定、備註、程式檢查結果、外形核對、驗收時的 `params_hash`）＋`reviewed_by`／`reviewed_at` |
| GLB／FBX／SKP | `product_models.furniture_model_id` 指回同一版本；SKP 沿用 `fds_request_skp` |

讀寫只經 RPC：`fds_save_furniture_model`、`fds_furniture_model_versions`、`fds_furniture_model_detail`、
`fds_review_furniture_model`、`fds_product_models`（見 `20261028100100_fds_furniture_model_versions.sql`）。

## 授權矩陣

| 操作 | admin | uploader | pm | designer |
|---|---|---|---|---|
| 看版本列表／版本詳情 | ✅ | ✅ | ✅ | ✅（未連產品的草稿只限作者） |
| 確認尺寸、編輯部件、保存草稿、生成新版本 | ✅ | ✅ | ✅ | ✅ |
| 驗收通過／不通過 | ✅ | ✅ | ❌ | ❌ |
| Tripo 提交 | ❌（已停用，RPC 及 `processing_jobs` 觸發器都拒絕） | ❌ | ❌ | ❌ |

角色檢查在 RPC 內（`bwf_assert_role`），不靠前端隱藏按鈕。驗收通過時伺服器再查一次：版本必須是
`pending_review`、程式檢查錯誤為空、外形核對已勾選、`params_hash` 與載入時相同（防止看舊版本按通過）。

## 前端流程

- 「已有模型」對話框先列版本（尺寸、狀態、檔案、修改自），可「以此版本修改」（不呼叫 AI）或「驗收」。
- 結構確認頁的「尺寸證據」區（`ModelEvidencePanel`）：衝突並排顯示、選值要寫理由、整組尺寸不會用在單件。
- 部件有固定 `part_id`，可複製、刪除（先列出受影響的接合）、鎖定軸向、改接合。
- 重新辨認部件不覆蓋現有部件，差異逐項顯示（`PartSuggestionPanel`），只採用勾選的項目。
- 驗收對話框（`FurnitureModelReviewDialog`）：程式檢查與人工外形核對分開；程式檢查包括用目前引擎重建並比較幾何。

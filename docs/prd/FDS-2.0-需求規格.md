# FDS 2.0 系統更新需求規格（PRD）

最後更新：2026-10-17

> **來源**：FDS 2.0 系統更新會議轉寫報告 ＋ 新版 Sitemap（Google Sheet）。
> **適用範圍**：OB 小型訂單報價、PP 大項目報價、設計師產品搜尋、廠家互動、PM 快速報價。
> **文件定位**：本文件為需求規格（做甚麼、為誰做、優先級）；逐頁的現況與實作說明見 `docs/prd/furniture-1000-overview.md`。

---

## 1. 背景與目標

### 1.1 現況痛點

| 編號 | 痛點 | 影響對象 |
|---|---|---|
| P-01 | B 類產品（約 3,000–4,000 款內部產品）只限傢俬組使用，設計師無法搜尋 | 設計師 |
| P-02 | 搜尋不夠精準（顏色、尺寸、類型），設計師需另在網上找圖，缺準確規格與價格 | 設計師 |
| P-03 | OB 細單報價無客戶互動（無 QR、無逐件確認、無版本追溯） | 客戶、PM |
| P-04 | PP 大項目報價無「分區」概念，方案不清晰、無法分區小計 | PM、客戶 |
| P-05 | 報價單靠複製再人手改，客戶修改後無法比對新舊版本 | 同事、客戶 |
| P-06 | 廠家產品更新靠人手「拆 Box」、手動更新，無停產／斷貨機制 | 傢俬組、採購 |
| P-07 | 無法辨別好廠家與差廠家（拖貨、質素不穩、保料問題） | 採購、PM |
| P-08 | 前端銷售（找單）與內部報價的 GP 無共識，出現「你賺我唔賺」 | PM、傢俬組 |

### 1.2 目標

1. 讓**設計師／PM／客戶**更快找到產品、完成設計與報價。
2. 報價流程可**互動、可追溯**：QR Code ＋ 版本控制 ＋ 每日 6:00 電郵／報告。
3. **開放 FDS 給全公司**（設計師、PM、其他同事），打破知識壁壘。
4. **供應商自助更新**，淘汰差廠家，資訊打通以支援公司由 70–80 人擴至未來 500 人。

## 2. 名詞定義

| 名詞 | 定義 |
|---|---|
| OB | 小型訂單報價（一般日常單） |
| PP | 大項目報價（項目制，常需分區） |
| A 類產品 | 約 800 款，已上網站，可公開搜尋 |
| B 類產品 | 約 3,000–4,000 款，內部用，目前限傢俬組使用 |
| 真單 | 已進入「打步下單」或確定客源階段（超過一半真實） |
| 假單 | 詐騙、不落實等無效報價 |
| GP | 毛利 |
| 中間價 | 賣價打八折，供 PM 快速報價基準，避免直接暴露成本價 |
| 分區 | 報價單內按空間劃分的分類（如 A 區入口處、Manager Room） |

## 4. 功能需求

優先級：**P0**＝優先開發；**P1**＝核心升級；**P2**＝後續／未來。

### R1 報價單客戶互動與版本管理（OB 細單為主）— P0

#### R1.1 QR Code 互動機制
- 每張報價單必須附帶 QR Code。
- 客戶掃碼後可直接查看報價單內容。
- 客戶可對**每件產品**回應：**確認／考慮／不確定**。
- 客戶可線上提出修改意見（常見：顏色、尺寸），系統即時回饋相關同事。
- QR Code 文案建議：「更多產品選擇」或「線上選擇／修改產品」，引導客戶進入互動。
- **驗收**：客戶掃碼 → 無需登入即可看到報價內容；逐件可選三種狀態；提交修改後同事端可見通知。

#### R1.2 版本控制（V1 / V2 / V3…）
- 客戶每次修改後自動產生新版本（V1 → V2）。
- 報價單需清楚顯示**「修訂日期」**及**「最新修改日期」**。
- 客戶可下載完整報價單，並可作電子簽名反饋（正式簽署仍可下載後簽回）。
- 系統保留**原版與修改版對比**功能，方便同事快速查看差異。
- **驗收**：修改後自動升版本並記錄兩個日期；提供新舊版本對比檢視；原版本不可被覆寫。

#### R1.3 客戶登入通知機制
- 客戶登入後，系統每日早上 **06:00** 自動發送電郵通知**相關負責同事**（非全組群發）。
- 電郵內容：哪張報價單有客人登入／修改，並附**直接連結**。
- 統計以**過去 24 小時**為準；**週末照常發送**，避免漏通知。
- 同事可透過連結即時查看原版與新版對比。

#### R1.4 每日動態報告（Daily Report）
- 每日早上 **06:00** 發送，涵蓋**過去 7 日／14 日／30 日**數據。
- 內容包括：
  - 各同事新增報價單數量
  - 成功機率／開單情況
  - 真單與假單分析（真單＝已進入「打步下單」或確定客源階段，超過一半真實）
- 用途：早會檢討——哪些同事需協助、工作如何重新分配、假單原因（詐騙、不落實等）。
- 目標：讓團隊更公平分配訂單與工作量。

### R2 分區報價功能（OB 與 PP 通用，PP 優先）— P0

#### R2.1 報價單類型區分
- **無分區報價單**：一般 OB 小型訂單使用。
- **有分區報價單**：PP 大項目或有分區需求時使用。

#### R2.2 分區欄位與功能
- 報價單**頂部加入「分區」欄位**。
- 可從 **PMS 系統拉入現有分區資料**，或**手動輸入**（例：A 區入口處、B 區辦公室右側、Manager Room、校長室）。
- 加入產品時可直接選擇所屬分區。
- 支援**按分區排序**產品。
- 可顯示**分區小計**（例：A 區 $15,000、B 區 $10,000，總計 $25,000）。
- 分區名稱需清晰，避免出現「經理房比老板房更貴」等不合理情況。
- **驗收**：報價單可建立多個分區、逐項指定分區、顯示分區小計與總計、可依分區排序。

#### R2.3 平面圖標注功能（針對 PP 大項目）
- 上載平面圖後，可在圖上直接標注分區（A/B/C/D 或熟悉名稱）。
- 標注完成後**自動產生對應分區**。
- 加產品時可選擇對應分區，使方案更清晰。
- 顯示每個分區的**件數、尺寸**等資訊。

#### R2.4 其他報價單功能調整
- 原「複製」功能改為**「客戶連結」按鈕**（小 icon 或文字），方便一鍵發送給客戶線上修改。
- **報價回收桶**功能保留，但需**增加確認提示**，避免誤刪。

### R3 設計師產品搜尋優化（核心痛點）— P0 / P1

#### R3.1 搜尋功能強化
- 產品類型 → **顏色篩選（支援多選顏色）**。
- 新增**「常用家私」**、**「最新產品」**快速篩選。
- 上載 PDF Catalog 時，**AI 自動切割分頁／分區**（例：第 1–17 頁辦公台、第 18–28 頁老板台、會議椅等）。
- 設計師搜尋時可直接看到對應 **PDF 頁面及圖片**，無需等待完整報價單分析。
- **優先顯示廠家現有款**，避免訂製過貴或不存在的產品。
- 支援更多 Filter：**材質（木皮面等）、尺寸、現貨／訂製**。

#### R3.2 開放權限（FDS 2.0 象徵）
- FDS **開放給全公司**（設計師、PM、其他同事均可搜尋）。
- 打破知識壁壘，讓所有人掌握全部傢俬資料。
- **內部下單**：設計師或同事可直接選產品並產生**「內部訂單」**給傢俬組。
- **成本價不直接顯示**給設計師；改用**「中間價」**或加一定利潤後的價格顯示。

### R4 廠家（供應商）互動與產品更新 — P1

#### R4.1 廠家自助上載
- 容許**廠家登入系統**，自行上載新產品、標記停產或斷貨。
- 上載後系統**自動通知**相關同事（設計師、PM）。
- 目標：減少人工拆 Box、手動更新，透過 API 連結 Box 管理檔案。

#### R4.2 產品更新與停產識別
- 每年對比報價單／Catalog，**自動識別停產產品**（編碼消失即標記）。
- 建立**「常用廠家」列表**（使用超過 3 次的廠家）。
- 廠家資訊、銷售表現、產品分類一併管理。
- 新同事可快速找到常用廠家及聯絡方式（解決「不知找哪間廠」）。

#### R4.3 痛點對應
- 好廠家要留、差廠家（拖貨、質素不穩、保料問題）要及早識別。
- 加強供應商互動，確保最新產品目錄與報價資料。

### R5 項目經理（PM）快速報價與專業 PDF — P1

#### R5.1 快速報價功能
- 新增**「項目經理報價／快速報價」**。
- 搜尋產品後可**即時生成初步 PDF**（含相片、尺寸、材質）。
- 支援**預算報價**與**正式報價**兩條路徑。
- 報價完成後可生成 **PDF 或 PPT**。
- 目標：讓 PM 快速取得報價，用於前端銷售。

#### R5.2 專業說明 PDF（不可反駁的報價單）
- 目標：讓客戶、老板或採購部覺得專業、難以反駁。
- 建議結構：
  1. 封面
  2. 報價內容
  3. 公司資質
  4. 成功案例／過往 Project Listing
  5. 服務承諾
  6. 廠家與產品介紹
  7. QR Code 連結至互動網站
- 可從**常用廠家（約 50 間）**中揀選 Catalog 頁面，**AI 自動生成**並加入 BW 品牌元素。
- 支援夾入指定產品 Catalog 頁面，並可修改廠家名稱為 BW 相關品牌。

### R6 其他功能與系統優化 — P1 / P2

#### R6.1 設計師工具
- 加入**「愛心小工具」**：SU 模型、3D 模型連結。
- 選中產品後可透過 **API 拉出模型**，供設計師畫圖使用。
- 更多 Filter 支援（產品類型、材質、尺寸等）。

#### R6.2 系統開放與資訊打通
- 傢俬系統不再只限傢俬組使用，**開放給全公司**。
- 目標：資訊打通，支援公司做大（由 70–80 人擴至未來 500 人）。
- 所有同事均可搜尋、選擇產品並產生**內部訂單**。

#### R6.3 廠家目錄與產品管理
- 上載 PDF 頁面名稱調整（**區分報價 PDF 與產品目錄**）。
- 廠家資訊、銷售表現、常用廠家、產品 PDF 一併呈現。
- 支援**成功案例展示**（知名客戶）。
- 廠家可登入更新資料，系統發送通知。

#### R6.4 軟裝與物料擴展（未來）— P2
- 未來可擴展**軟裝**（藝術品、窗簾、燈飾等）與**物料管理**，讓部門更完整。

#### R6.5 系統設定：電郵通知記錄與管理項 — P1
- **電郵通知（系統設定 → `fds2-admin-email`）需設「發送記錄」**，記錄每一封由系統發出的電郵：
  - R1.3 客戶登入通知（每日 06:00）
  - R1.4 每日動態報告（每日 06:00）
  - R4 廠家上載／產品更新通知
- 記錄欄位：**發送時間、收件人、通知類型、關聯報價單／產品、發送狀態（成功／失敗）、失敗原因**。
- 用途：供管理員查核與排錯（例：客人登入後，相關同事是否真的收到通知）。
- **驗收**：每封系統電郵均留一筆記錄，可在「系統設定 → 電郵通知」檢視、篩選與重發。
- 同區管理項維持並列入 Sitemap：**PRD功能描述**（`fds2-admin-prd`）、**每日指令記錄**（`fds2-admin-command-logs`）、**開發成本**（`fds2-admin-dev-cost`）。

## 5. 定價與 GP 規則（內部討論重點）

| 項目 | 規則 |
|---|---|
| 傢俬組 → PM 報價基準 | 建議用**賣價打八折**（中間價），避免直接暴露成本 |
| PM 加成 | PM 可在此基礎上加自己的 **GP，建議 15–20%**（而非 30%） |
| 原則 | **雙方都有錢賺**，避免「你賺我唔賺」的衝突 |
| 前提 | 前端銷售（找單）最難也最貴，需共生生贏 |
| 待辦 | 現有報價已含折扣，內部流程需**重新對齊** |

> **狀態**：**已決議（2026-10-19）**——賣價 × 0.8 為中間價，適用全部產品類別；PM GP 15–20%。詳見 FDS 2.1 §17。

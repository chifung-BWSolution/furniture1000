## 1. 為什麼做 V2.2

FDS 已經能管產品、跑 AI 識圖、做報價和設計專案，但贏標仍被幾件事拖住：

1. 廠家圖冊、報價單、產品資料沒有連成同一筆可追溯記錄。
2. 圖片和實際可採購產品可能不一致；生成式預覽被當成實物會引發投訴。
3. 大量廠家 PDF 仍靠人工翻頁。
4. 設計師拿不到能放進效果圖軟件的模型檔。
5. PM 的套餐式快速報價仍在獨立 Google Sheet。
6. 提案 PPT 要人手拼產品、圖冊和成功案例。
7. 客戶看完報價後，選品和加單不夠直接。
8. 廠家說明在 FDS 與 Asana 各寫一次。

會議要求系統解決「幾千件產品、幾百間廠」的查找與準確度問題，而不是再堆一層內部工具。V2.2 的價值是讓團隊報得準、出得快、提案看起來完整。

### 1.1 產品目標

| 目標 | 預期效果 |
|---|---|
| 家具資料統一 | 圖冊、報價單、產品型號連在一起，並能追到頁碼 |
| AI 自動化 | 減少手工鍵入和翻 PDF |
| 設計效率 | 設計師找到真實可採購產品，並下載可用模型 |
| 快速報價 | PM 輸入數量即時得到參考價 |
| 專業提案 | 固定結構的 PPT，加上圖冊頁附件 |
| 客戶互動 | 客戶用授權連結查看、選品、提交加單 |
| 數據整合 | 價格、廠家說明、行業可追溯；Asana 不重複維護 |

### 1.2 版本邊界

- 不重構 QMS、PMS。
- 不重建已經在用的 FDS 模組。
- 優先擴出現有資料表、API 和畫面。
- 改動保持向後相容。新功能不得破壞既有報價、產品和文件。
- 角色沿用現有 FDS 權限，不另建一套平行權限。

| 角色 | 主要工作 |
|---|---|
| System Admin | 系統配置、分類、基準價格、使用者權限 |
| FDS Admin | 廠家資料、PDF 上傳、AI 結果審核 |
| Designer | 搜尋選品、下載設計檔、做方案 |
| PM | 快速報價、PPT、客戶報價與跟進 |
| Customer | 經授權連結查看報價、選品、提交需求 |

### 1.3 現有系統基線（實作時必須沿用）

以下能力已經在本倉庫，V2.2 是補齊缺口，不是重做。

| 能力 | 現況 | V2.2 怎麼接 |
|---|---|---|
| 廠家目錄 | `ManufacturerDirectoryView`，經 `supabase-functions-fetch-manufacturer-directory` 列廠家 | 在現有廠家上記錄圖冊／報價單／年份，不另建廠家主檔 |
| PDF 上載與 AI | `AIProcessorView`，模式含 `pdf-catalog`、Excel，呼叫 `supabase-functions-gemini-pdf-catalog` | 圖冊與報價單共用「廠家 + 型號」匹配，不開第二套入庫 |
| 顏色 | `src/constants/color-map.ts` 的中英對照 | 沿用，不新建顏色體系 |
| 客戶產業 | 快速報價已可多選，選項來自 PMS 行業標籤 | 成功案例與公司主檔沿用同一套，不在 FDS 自建行業樹 |
| 報價與客戶連結 | `bwf_quote`、`QuotationDraftEditor` 已能產生分享 token 與 QR | PDF 要嵌入這個連結的 QR；停止把連結交給第三方 QR 圖床 |
| 平面圖分區 | 方案列表可上傳平面圖；`ProjectPartitionPanel` 與 `projectPartitionTemplates.ts` 已有分區 | PPT 與效果圖讀這套分區，不另做第二套區域 |
| 現有快速報價 | `QuickQuoteView` 是 PMS pitching 報價精靈，寫入 `bwf_quote` | 保留。FDS-08 的套餐計價是旁邊的新流程，不改寫 pitching 報價 |
| 成功案例頁 | `CustomerCaseStudiesView` 是靜態公開案例 | 內部可篩選案例庫做好之後，才供這頁和 PPT 引用 |
| Asana | 目前只有 `asana_link` 按鈕 | 雙向同步是新能力，Asana 為 Description 的主資料 |

## 2. 已拍板決策

會議口語和草案用詞不一致的地方，收成下面這些規則。

| 議題 | 決定 |
|---|---|
| 3D 交付物 | 設計師要的是可下載、可匯入效果圖軟件的檔。主格式是 **SKP** 與 **FBX**。GLB 只可作為中間或預覽交換格式，不作為主按鈕名稱。會議提到的 SDK／SPK 視為 SKP 的口誤，不另做格式 |
| 互動式 3D | Tripo 等可旋轉預覽優先級降低。客戶若看得到，必須標示「僅供參考」。不得把 AI 預覽當成實物圖。固定使用真實廠家圖片更安全 |
| 模型轉換 | 只改副檔名不算完成。必須走該格式的生成或轉換，並由設計師實際打開驗證 |
| 圖冊附件 | 報價可同時帶主產品圖和圖冊抽出的頁。支援不連續頁（例如第 2、34、64 頁），可跨 PDF，再合併進報價輸出 |
| 顏色 | 沿用現有一級／二級顏色。圖片推測與廠家圖冊／報價單上的顏色寫入同一組顏色，不分開存放。AI 不得自建正式色名。無法對上的進人工審核。「訂造」是標記，不是新色庫 |
| 行業 | 一間公司或一個項目可以有多個一級／二級行業。結構跟 Leo 確認的 PMS 行業標籤走，FDS 不另建分類樹 |
| PPT 結構 | 固定五段，順序不可改：封面、公司介紹、平面圖、方案、參考案例。每段可多頁。沒有平面圖就略過該段。不做自由拖拉編輯器 |
| 超過 10 個報價項 | 提示建立分區，不強制擋下輸出。分區數量不限於 A／B／C／D |
| 報價 QR | 報價 PDF 與快速報價 PDF 嵌入指向現有分享連結的 QR。QR 在系統內生成，不呼叫 `api.qrserver.com` 這類第三方圖床 |
| 價格 | 不對缺漏價格做 AI 推測。同年同型號價格衝突時不自動挑選。新文件不覆蓋歷史報價。快速報價基準價變更不改寫已輸出的舊單 |
| Asana | 雙向寫入，Description 衝突時以 Asana 為準。Comment 只追加，並去重 |
| AI 效果圖 | 只供內部參考。人工確認前不得進入對外 PPT |
| 客戶改價 | 客戶不能改正式報價單價格。選品與加單以郵件通知負責 PM |
| 郵件模板 | 每張報價單一份可編輯模板。預設三段：內容簡述、有問題可電話聯繫、加單連結；三段之外可再加自訂內容。報價單詳情有「郵件模板」按鈕，可編輯並手動發送。客戶從加單連結成功進入頁面時埋點並通知負責 PM |
| 自動跟進 | 每 3 天一封，用該報價單自己的模板。該報價頁被授權使用者成功載入後停止。郵件圖預載或掃描不算「已查看」，也不觸發 PM 通知 |
| 文件解析時段 | 圖冊與報價單可以先上傳。上傳只保存原檔並建立待解析任務，不立刻解析。AI 解析只在 Asia/Shanghai（UTC+8）每天 23:00 至翌日 09:00 進行，09:00–23:00 的工作時間不啟動、不續跑 |

## 4. FDS-01 廠家資料與 PDF 管理

集中查找廠家的圖冊、報價單和產品。家具廠家優先顯示。

### 4.1 列表

| 欄位 | 說明 |
|---|---|
| Manufacturer | 廠家名稱 |
| Category | 家具／材料／其他 |
| Product Categories | 主要產品分類 |
| Cooperation Status | 只顯示已有合作記錄能支持的狀態 |
| Last Cooperation | 最近一次有記錄的合作時間 |
| Catalog | 是否已有圖冊 |
| Price List | 是否已有報價單 |
| Latest Year | 最近文件年份 |
| AI Status | 文件分析狀態 |

列表可按名稱搜尋，按廠家分類、家具類型篩選，按合作記錄排序，並篩出尚未上傳圖冊或報價單的廠家。可進入廠家詳情與文件頁。沒有合作記錄時不得顯示成「沒有合作」。

### 4.2 上傳

本階段文件類型：Catalog（圖冊）、Price List（報價單）、Certificate（證書）。安裝影片不做。

| 欄位 | 必填 | 說明 |
|---|---|---|
| Manufacturer | 是 | 所屬廠家 |
| File Type | 是 | 上列三類之一 |
| File | 是 | 原始檔 |
| Year | 是 | 文件年份 |
| Series | 圖冊必填 | 系列，供之後搜尋 |
| Product Categories | 圖冊必填 | 主要產品類型 |
| Version | 否 | 同年份版本 |
| Description | 否 | 備註 |
| Uploaded By / At | 自動 | 上傳人與時間 |
| Processing Status | 自動 | AI 狀態 |

規則：同廠多家年份、同年多版本；新檔不覆蓋舊檔；歷史檔可看可下載；每份文件保留自己的分析記錄與來源關聯。上傳成功即可離開。圖冊與報價單上傳後只保存原檔，狀態為待解析，不在上傳當下啟動解析。

圖冊和報價單共用同一個上傳畫面、同一份文件清單，也共用產品管理裡的一個選單（廠家目錄）。兩者只以文件類型區分：圖冊要填系列和主要產品類型，報價單不必。不再另設「上載PDF」選單。

### 4.3 驗收

- 可建立並管理三類 PDF。
- 同廠、同年可留多個版本。
- 能搜出文件未齊的廠家。
- 上傳不等待分析，也不會因上傳而立刻開始解析。
- 新文件不刪掉歷史文件和既有產品關聯。

## 5. FDS-02 AI 圖冊及報價單統一識別

圖冊和報價單按產品型號配成一筆產品記錄。原始 PDF 永遠保留。不拆成兩套入庫流程。

### 5.1 圖冊要抽的欄位

Product Name、Model、Manufacturer、Product Images、Category、Series、Material、Dimensions、Primary Color、Secondary Color、Original Color、Source Page。圖片推測色與文件上的顏色都映射到同一組 Primary／Secondary Color。Original Color 只保留廠家原文，不成為第二套顏色。同時建立圖冊目錄與頁碼索引，供附件選頁使用。

### 5.2 報價單要抽的欄位

Manufacturer、Model、Product Name、Specification、Unit Price、Currency、Unit、Source Document、Source Page、Year／Version。

缺價格就留空，標記未匹配。禁止生成推測價格。

### 5.3 流程

1. 上傳 PDF 並保存原檔。上傳請求到此結束，不呼叫解析。
2. 建立分析任務，狀態為 Pending，等到解析時段才開始。
3. 在解析時段內抽文字、頁面和產品候選。
4. 以廠家 + 型號對上圖冊與報價單。
5. 合併已能確認的欄位，做顏色映射。
6. 高置信度入庫，低置信度進待審核。
7. 更新搜尋索引。

任務狀態：Pending、Processing、Completed、Failed、Review Required。上傳與分析拆開。可背景批量、可重試、可看進度與錯誤。

解析時段（Asia/Shanghai，UTC+8）：

- 只在每天 **23:00 至翌日 09:00** 執行圖冊與報價單解析。
- **09:00–23:00 不啟動新任務，也不續跑**已開始的解析。跨過 09:00 時應停在可恢復的進度，下一個 23:00 再繼續，不得在工作時間佔用解析資源。
- 白天上傳的文件留在 Pending，當天 23:00 之後才處理。晚上上傳同樣不在上傳請求裡立刻解析，只由該時段的排程領取。
- 證書只保存，不進入這個解析排程。

### 5.4 驗收

- 兩種文件都能認出來源內容。
- 同一廠家的相同型號能合成一筆產品。
- 每筆提取能回到原檔與頁碼。
- 分析失敗不影響原檔。
- 在 09:00–23:00（Asia/Shanghai）上傳圖冊後，任務保持 Pending，沒有解析請求被發出。
- AI 推測不得當成已確認價格或規格。

## 6. FDS-03 產品匹配、價格及顏色

### 6.1 型號

匹配順序：Manufacturer、Product Model，Specification 只作輔助。同廠同型號優先合併。不同廠的相同型號字串不得自動合併。型號殘缺或有歧義則進審核。一筆產品可掛多份圖冊和多個歷史報價版本。

### 6.2 價格版本

- 預設採用最新年份的有效報價。
- 保留全部歷史價格，可看來源與年份。
- 沒有有效價格則標「未匹配價格」。
- 同一型號、同一年份出現衝突價格時，不自動選一個，等人確認。
- 新文件不得直接蓋掉歷史報價。

### 6.3 顏色

沿用現有一級、二級顏色（實作起點是 `src/constants/color-map.ts`）。先盤點現有分類的使用情況，再把識別結果映射過去。對不上就人工審核。AI 不得新增正式顏色分類。

圖片推測出來的顏色，和廠家圖冊或報價單寫明的顏色，都寫入同一組一級／二級顏色。不另建「圖片推測色」和「廠家常規色」兩套欄位，也不把兩者當成不同的顏色來源。廠家原始色名只作對照文字，篩選與展示都用映射後的那一組顏色。

訂造色標記為「訂造」，表示要另作溝通，不寫進常規色庫。產品類型篩選優先於顏色篩選。

### 6.4 驗收

- 新舊報價並存時，有效價取最新年份。
- 歷史價格追得到。
- 圖片推測與廠家文件上的顏色落在同一組既有分類，或進入審核。
- 不會出現系統不認識的新正式色。
- 價格衝突和型號歧義在畫面上認得出、處理得了。

## 7. FDS-04 AI 產品入庫及審核

高置信度自動入庫；低置信度進待審核。狀態優先復用產品庫已有值；若沒有，使用 Auto Imported、Pending Review、Approved、Rejected。

審核人員可看原 PDF、頁碼和 AI 結果，並修正名稱、型號、分類、規格、顏色、價格對應，然後確認或拒絕。

驗收：高置信度自動入庫；低置信度不以已確認產品發布；審核可更新產品；原始 AI 結果與人工修正都留痕；同一文件重試不得無限複製產品。

## 8. FDS-05 家具搜尋及設計師分享

搜尋條件：產品名稱、型號、家具類型、廠家、系列、材質、尺寸、一級顏色、二級顏色。

結果顯示：產品圖片、名稱、型號、廠家、規格摘要、價格資料狀態、可用設計文件（含 SKP／FBX 是否已有）。

設計師可建產品選擇集合並分享給效果圖設計師。分享含已選清單、圖片、型號規格、相關設計文件。沿用 FDS 權限。供應商成本和其他內部敏感欄不得經分享連結流出。

## 9. FDS-06 SKP／FBX 模型

產品上的含糊「生成 3D」改為兩個明確動作：

- 生成／下載 SKP
- 生成／下載 FBX

要求：格式與按鈕一致；顯示生成狀態；完成後可下載；失敗有錯誤訊息。僅改副檔名不算完成。本階段不做「單張照片重建完整家具結構」。

互動式預覽可以留下，但不是這項需求的完成定義。任何客戶可見的預覽都要標「僅供參考」。

驗收：按鈕名稱正確；檔案能用對應軟件打開（由 Amy 或指定設計師試導入）；失敗狀態看得懂。

## 10. FDS-07 PDF 圖冊剪貼與報價附件

使用者從廠家圖冊取出頁面或局部圖，加進報價和提案。報價輸出同時包含主產品圖與這些補充頁。目的是讓報價附件完整，而不是只有一頁單價。

流程：

1. 選廠家圖冊（已標年份、系列、產品類型，方便搜尋）。
2. 在線預覽 PDF。
3. 選整頁，或半頁／框選。
4. 可重複選不連續頁，也可混用不同 PDF。
5. 加入目前提案或報價的附件清單並排序。
6. 選擇對外文件是否顯示廠家與來源頁碼。
7. 與報價內容合併輸出。

要求：不隨意裁掉原圖細節；保持清晰度；未選擇顯示來源時，對外文件不出現來源標籤。

驗收：三個不同 PDF 的選定頁能合成一份附件；局部裁剪可用；不同比例正常輸出；隱藏來源時標籤不出現。

## 11. FDS-08 PM 套餐式 Quick Pricing

這是獨立於現有 pitching「快速報價」的參考計價。業務規則以 BWF Quick Pricing Google Sheet 為準：

https://docs.google.com/spreadsheets/d/1dsHI6pd8UcynkddFw01heLFpaNAWevkf2YH1mT35edU/edit?gid=664577347#gid=664577347

PM 不必先選正式產品型號。填數量後即時得到參考價。欄位以核實後的工作表為準，預期包含 Area、Item、Material、Dimension、Unit、Quantity、Average Price、Basic Package Price、Mid Package Price、Subtotal、Total。

流程：進入 Quick Pricing → 載入預設項目 → 改 Quantity → 即時重算 → 顯示分區小計與各配套總額 → 可出快速參考報價 PDF。

計算：

- Item Subtotal = Quantity × Unit Price
- Total = 適用項目小計之和 + 適用附加費

運輸、安裝和其他附加費逐項對照工作表公式。不得自訂固定比例，也不得用 AI 生成報價數字。管理員維護基準價。可看歷史價格參考。改基準價只影響新單，不靜默改舊輸出。

PDF 含：標題、分區與項目、尺寸與單位、數量、對應配套價格、小計與總額、適用附加費、參考報價說明，以及指向該單分享連結的 QR（若此單已有客戶連結）。

驗收：改數量即時更新；各配套各自計價；小計與總額一致；新單用新基準價；PDF 與畫面一致；數量為 0 的項目不產生正數小計。現有 `bwf_quote` pitching 報價仍可照常開立與分享。

## 12. FDS-09 PPT 自動生成

固定五段，每段可多頁：

1. **封面：** Logo、項目名稱、客戶名稱、封面圖、日期。
2. **公司介紹：** 背景、優勢、主要服務、專業資質、相關能力。這段內容集中維護、可重用。
3. **平面圖：** 上傳的圖、區域名稱、A／B／C／D 或其他代號。沒有平面圖就略過整段。
4. **方案：** 按項目與分區顯示家具圖、名稱型號、規格、數量、報價資訊、從圖冊選出的補充圖。項目多時自動分頁。超過 10 項時提示分區，不阻止生成。
5. **參考案例：** 依本項目選出的成功案例：名稱、客戶或品牌、行業、項目圖、簡介。

生成步驟：選項目或方案 → 載入模板與公司介紹 → 載入平面圖分區 → 載入方案產品 → 選圖冊補充 → 選案例 → 預覽 → 下載 PPT。

驗收：順序正確；內容多時自動加頁；無平面圖仍能生成；圖片比例正常；產品與區域一致；檔案可打開。不提供自由編輯器。未審核的 AI 效果圖不得自動進檔。

## 13. FDS-10 平面圖分區

在現有設計專案平面圖上建立區域，並把報價項目指派進去。供 PPT 與後續 AI 場景圖使用。

流程：上傳平面圖 → 建立區域 → 設定代號與名稱 → 指派 Item → 保存 → 可再改。

欄位：Floor Plan、Zone ID、Zone Name、Zone Position、Related Items。

規則：項目可以沒有平面圖；分區數不限四個；A／B／C／D 只是預設展示；一個區域可有多個產品；已存分區可修改。分區資料寫入現有設計專案，不另開一套區域模型。

## 14. FDS-11 成功案例

把已有項目整理成可搜尋、篩選、匯出的資料。客戶常問有沒有做過某類機構（例如 NGO、學校）。內部篩選要能回答這件事。

篩選：項目名稱、客戶、行業、項目類型、家具類型、項目金額、日期範圍、項目經理、品牌。

一間公司或一個項目可有多個行業標籤（一級、二級）。標籤來源是 PMS，由 Leo 確認結構後接入。FDS 不自建行業主檔。

案例可選圖、可選要展示的欄位（含員工相片、金額、時間，僅在來源資料存在時顯示），可送進 PPT 參考案例，也可輸出給客戶看的版本。與 PMS 對接以便匯出，不在 FDS 複製一份會漂移的項目主數據。

現有客戶專區「成功案例」維持公開內容，直到內部案例庫有可發布資料再接上。篩選頁不得用靜態文案假裝已篩選。

## 15. FDS-12 Asana 雙向同步

避免廠家說明在 FDS 和 Asana 各寫一次。雙向寫入，**Asana 為主**。

第一期只同步 Description 與 Comment。

- Asana 的更新同步到 FDS。
- FDS 的更新可寫回 Asana。
- Description 衝突時以 Asana 為準。
- Comment 只追加，不覆蓋歷史留言。
- 已同步的評論要認得出，重試不得重複建立。
- 保留同步狀態與錯誤記錄。

批量上載圖冊的同事（Rachel／Michael）在補廠家資料時使用這條關聯，而不是只在 FDS 貼一段文字。

驗收：廠家可對上 Asana 物件；Description 同步方向符合上列規則；Comment 雙向追加且不重複；衝突時 Asana 優先。

## 16. FDS-13 AI 空間效果圖（P2）

依平面圖、分區和區內已選家具生成室內參考圖。流程：選平面圖 → 選分區 → 載入該區家具 → 生成 → 人工檢查 → 確認後才可用於對外提案。

方向是實際選定家具的簡潔空間示意，可評估 45 度俯視。初期不要求高精度室內建模。未審核圖片不得進入正式對外 PPT。

## 17. FDS-14 客戶互動報價（P2）

客戶用授權連結查看報價，並選擇或加感興趣的家具。沿用現有報價分享連結與客戶專區，不另做入口。

頁面需桌面與手機可用，可看方案、圖片、規格、已報價產品、同類產品，可改選、提出加單或替換，並提交。提交後郵件給負責 PM。客戶不能改正式報價價格。

提交內容：相關報價、所選產品、數量、修改或加單需求、提交時間。本階段不做自動折扣；折扣由 PM 確認。

驗收：授權連結打得開；可看產品；可提交選品與加單；PM 收到通知；正式報價不被客戶操作改寫；連結不能拿到其他報價或內部成本。

## 18. FDS-15 郵件模板與自動跟進（P2）

發信身份使用部署環境配置的系統信箱（`system@…`），不寫死在前端。手動發送與自動跟進都用同一份模板。

### 18.1 每張報價單一模板

每張報價單對應一份固定模板，存在該報價上，可編輯。改 A 單的模板不影響 B 單。不另做全站共用範本。

報價單詳情增加「郵件模板」按鈕。打開後可編輯這張單的模板，並可手動發送。

預設三段，順序固定，不可刪掉：

1. **郵件內容簡述**：這張報價要客戶先看懂的摘要。
2. **有問題可以電話聯繫**：寫出可聯絡的電話。電話取這張報價已有的負責同事電話，不另建通訊錄。
3. **加單連結**：指向這張報價的現有授權頁。客戶由此查看、選品、加單或替換。連結沿用現有分享 token，不新做入口。

三段之外可以再加自訂內容（這張單要多寫的說明、期限、注意事項）。自訂內容可空、可改，不取代上面三段。

### 18.2 發送

可手動發送，也可自動跟進。自動跟進每 3 天一封，內容就是這張單當下的模板。客戶首次有效打開該報價的授權頁面後，只停止這一張報價的自動信。客戶另提交選品或加單時，另外通知負責 PM（FDS-14）。

### 18.3 點進加單連結要埋點並通知 PM

客戶點郵件裡的加單連結，授權頁成功載入時記一筆查看事件，並通知負責 PM。事件至少留下：哪張報價、何時進入、對應哪一次發信。

「有效打開」指授權頁成功載入。郵件圖片預載、安全掃描、機器人請求不算查看，不寫埋點，也不通知 PM。

狀態：Not Sent、Sent、Auto Follow-up Active、Viewed、Stopped。

驗收：報價單詳情看得到「郵件模板」；每張單各存各的模板；預設三段都在，且可附加自訂內容；可手動發送；自動信沿用該模板、間隔 3 天；客戶從加單連結成功進入後有埋點且 PM 收到通知；有效查看後不再催；同一報價不會排出多份重複排程；圖片預載與掃描不觸發通知。

## 20. 非功能需求

- 套餐報價改數量後畫面即時更新。
- 大型 PDF 上傳不堵住其他功能。AI 解析只在 Asia/Shanghai 23:00–翌日 09:00 的排程中跑，上傳本身不觸發解析。

- 內部功能以桌面為主；客戶報價頁要能用手機。

- 沿用 FDS 現有視覺，不另起一套 UI。
- 重傳文件不得無限複製；不同年份圖冊不得因此拆成多筆錯誤產品；失敗任務不得破壞已確認資料。

具體毫秒數與容量在現有環境做基準測試後再定，不在本規格裡寫空指標。

## 21. 分期驗收

### Phase 1 — 廠家資料

廠家清單、PDF 上傳、多年份版本、非同步分析、圖冊與報價單提取、型號匹配、顏色映射、入庫與審核。

用一組含多年份圖冊、報價單和重複型號的真實檔，檢查是否得到正確且可追頁碼的產品，低置信度是否進人工。

### Phase 2 — 報價與提案

套餐 Quick Pricing、基準價維護、快速報價 PDF、圖冊剪貼、平面圖分區、固定 PPT、成功案例引用、報價 PDF QR。

PM 能依預設家具和數量完成參考報價，並把產品、圖冊頁和案例組成客戶提案。

### Phase 3 — 設計檔與客戶互動

SKP／FBX 實檔試用、AI 空間圖（經人工確認）、客戶在線查看、選品加單、PM 通知、郵件跟進。

客戶從郵件加單連結進入（埋點並通知 PM）、提交需求（再通知 PM），且該報價在首次有效進入後停止自動催信。

Asana 同步視接口與權限插在資料建設過程中，不單列成阻塞 Phase 1 的前置專案；沒有權限時保持現有連結按鈕，並把錯誤記下來。

## 22. 驗收場景

**場景 A：廠家導入。** 同一廠家上傳多年份圖冊和報價單。背景識別後，相同型號合成一筆產品，價格按版本保留，低置信度進審核。

**場景 B：設計師選品。** 按類型、顏色、廠家找到產品，看到真實圖片與規格，下載 SKP 或 FBX，並把清單分享給效果圖設計師。分享連結沒有成本價。

**場景 C：PM 套餐報價。** 打開預設 Quick Pricing，輸入數量，畫面即時算出基本、中級和平均參考價，PDF 與畫面一致並帶 QR。既有 pitching 報價不受影響。

**場景 D：提案。** 選擇項目、平面圖、產品、圖冊頁和案例。系統按「封面、公司介紹、平面圖、方案、參考案例」出 PPT。沒有平面圖時跳過該段。未審核效果圖不在檔內。

**場景 E：客戶互動。** PM 在報價單詳情打開「郵件模板」，確認簡述、電話和加單連結，必要時加上自訂內容，並手動發送。客戶點加單連結進入頁面，系統埋點並通知 PM。客戶再提交加單，PM 再收到一封。正式價格不變。該報價的自動跟進在首次有效進入後停止。

**場景 F：Asana。** Description 與 Comment 同步。Description 衝突採 Asana。同一則 Comment 不會因為重試出現兩次。

## 26. 總結

V2.2 把 FDS 從家具資料庫推進到一條工作鏈：

**廠家上傳圖冊與報價單 → AI 識別 → 型號與價格匹配 → 統一產品庫 → 設計師選品並下載 SKP／FBX → PM 套餐報價或正式報價 → 圖冊附件與五段 PPT → 客戶查看選品 → PM 跟進。**

三項結果：

1. **資料準。** 產品、圖片、型號和真實廠家報價連得起來，生成預覽不會被當成實物。
2. **做得快。** 少翻 PDF、少找家具、少手工拼報價和 PPT。
3. **更好贏標。** 報價附件完整，提案結構固定，客戶能選品加單。

實作前仍須核對現有程式、資料庫和 Google Sheet 公式。第 23 章沒有答案的項目，不得自行當成最終業務決定。

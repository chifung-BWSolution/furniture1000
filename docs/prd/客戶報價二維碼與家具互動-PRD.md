# FDS 客戶報價二維碼與家具互動 PRD

版本 1.0｜2026-11-06｜二維碼流程已確認，其餘需求供開發及驗收

## 目標與入口

客戶掃描報價上的二維碼後，直接進入該張報價的分享頁 `/customer?quote_share=…`。客戶先看到報價內的家具、圖片（如有）、數量、單價及小計，然後可在同一頁瀏覽適合客戶項目工程類型的其他家具，提出加選或換款，亦可確認現有報價。負責同事在 FDS 查看提交內容，並收到電郵跟進。

## 產品規則

- **分享與身分**。首版擬沿用免登入的報價專屬連結。通知使用「報價已查看」，避免將持有連結等同客戶本人完成登入。若業務要求核實客戶身分，再決定是否加入 OTP。
- **排序與回退**。以客戶對應設計專案的工程類型為第一順位，沒有關聯專案或未設定時才用已關聯的 PMS 客戶行業。兩者均缺少或沒有相符商品時，顯示正常 A 類目錄。用途是排序依據，客戶仍可主動瀏覽其他分類。
- **提交與正式報價**。加選、換款和確認都綁定報價版本，並留下操作、數量、時間及備註。加選與換款先保存為待處理請求，由 PM 覆核後處理正式報價。客戶確認記錄其對指定版本的決定，後續訂單及付款沿用既有業務流程。
- **授權與價格**。伺服器校驗分享連結、報價版本、原項目歸屬及目錄商品資格。商品資料從目錄讀取，前端傳入的價格只可用於顯示。重新提交同一請求須去重。
- **通知**。建議每張報價首次有效查看通知一次，每次成功提交加選、換款或確認再通知。電郵包含報價單號與版本、動作、涉及項目及數量、備註及跟進入口。預設寄報價負責同事，Luca 是負責人時便寄給 Luca。找不到收件人或發送失敗時，在內部面板顯示狀態並沿用重試流程。
- **沿用現有資料**。以 FDS 的報價分享、產品目錄、客戶提交及通知能力為主，使用 PMS 既有客戶行業資料。優先擴充現有提交資料與驗證，保留原有報價及 PMS 契約。

## 驗收條件

1. 保存一張新報價後，可直接點「獲取二維碼」。重開同一版本或連續打開彈窗，仍取得同一個有效連結。PDF 與彈窗二維碼掃描後開啟同一張報價。切換到另一張報價時，頁面及 PDF 均使用新報價所屬的二維碼。
2. 手機用有效連結打開時先看到原報價家具。失效連結無法讀取明細，也無法提交。未保存的報價顯示保存提示。
3. 分別用辦公室、學校和醫療診所的設計專案核對首批推薦。沒有工程類型、沒有關聯專案或無匹配結果時仍能瀏覽家具。其他用途的 A 類家具可透過目錄入口查看。
4. 加選一款新家具，再用另一款替換原項目。PM 可看到兩種請求的內容，正式報價明細與總額維持提交前的數值，直到 PM 處理。重複提交同一請求只產生一筆紀錄。
5. 分別用有及沒有設計專案關聯的報價完成整單確認。確認回執、PM 面板及通知須顯示同一報價版本。
6. 用測試信箱驗證查看、加選、換款和確認通知。重複查看按確認後的頻率去重。找不到 PM 電郵時，面板顯示待處理原因，客戶提交仍保存成功。

## 待定與發布

二維碼自動生成、按鈕名稱及客戶頁入口已確認。上線前需定案免登入連結是否加 OTP、工程類型與商品標籤的對照及維護方式、首次查看的通知去重口徑，以及 Luca 是否需要在非負責人時也收通知。已撤銷連結的舊二維碼須維持失效，新連結自動簽發的規則須與邀請管理的撤銷用途一致。

先在 FDS 開發環境使用測試報價及測試信箱驗收，再核對正式環境的分享、客戶提交、通知工作程式及排程，最後以手機完成掃碼至 PM 收信的流程。程式已有功能與正式環境驗收分開記錄。
